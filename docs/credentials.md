# Credentials and local secrets

## What is already configured locally

The root `.env` contains browser-safe local values only. `.env.local`, generated by the Convex CLI, selects the local deployment and contains its local URLs. Both files are ignored by Git.

`pnpm keys:generate` creates ignored material under `.local/` and `pnpm convex:env:local` loads it into the selected local Convex deployment. The generated set includes:

- a 3072-bit RSA signing key and public JWKS for five-minute Convex JWTs;
- a Privy-compatible P-256 authorization keypair;
- a valid local Svix-format webhook signing secret;
- random mock app-secret material; and
- explicit local-only mock-auth configuration.

Do not copy the mock app ID, app secret, webhook key, or verification-key placeholder into a real Privy environment. Never commit or share `.local/convex.local.env` or `convex-auth-private.pem`.

## Values that must come from your Privy account

Open [Privy Dashboard](https://dashboard.privy.io), select the development app, and collect these values:

| Application value             | Privy Dashboard location                                            | Destination                                                  |
| ----------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------ |
| App ID                        | **Configuration → App settings → Basics**                           | `PUBLIC_PRIVY_APP_ID` in `.env` and `PRIVY_APP_ID` in Convex |
| App Secret                    | **Configuration → App settings → Basics**                           | `PRIVY_APP_SECRET` in Convex only                            |
| Client ID                     | **Settings → Clients**                                              | `PUBLIC_PRIVY_CLIENT_ID` in `.env`                           |
| Access-token verification key | **Configuration → App settings → Basics → Verify with key instead** | `PRIVY_JWT_VERIFICATION_KEY` in Convex only                  |
| Webhook signing key           | **Configuration → Webhooks** after creating the endpoint            | `PRIVY_WEBHOOK_SIGNING_KEY` in Convex only                   |

The App ID and Client ID are browser-visible identifiers. Every other value is a backend secret. Privy does not retain recoverable copies of an app secret or authorization private key; rotate/regenerate a lost value.

## Authorization signer

The setup script already generated a valid P-256 key using Privy's installed Node SDK. Register the contents of `.local/privy-authorization-public.txt` from the Privy Dashboard **Authorization Keys** page. Keep the corresponding private key inside Convex; it is already loaded locally as `PRIVY_AUTHORIZATION_PRIVATE_KEY`.

The live smoke harness can instead register that public key in a development-only 1-of-1 key quorum automatically. This is useful for validating API contracts, but it is not a substitute for the 2-of-3 human reviewer quorum used by the showcase.

For a real production environment, generate a separate P-256 key, register only its public half, and store its private half in the production Convex deployment or a supported KMS. Never reuse the local-development signer.

After inviting the three reviewers, each reviewer enrolls biometric or TOTP MFA from **Account preferences → MFA enrollment**. Create a key quorum with those members and threshold `2`, then assign it as the owner of the treasury wallet and management policies.

## Load real secrets without shell-history leakage

Select the intended deployment explicitly. On Windows, copy one secret from Privy and pipe it from the clipboard:

```powershell
Get-Clipboard | corepack pnpm exec convex env set PRIVY_APP_SECRET --deployment local
Get-Clipboard | corepack pnpm exec convex env set PRIVY_JWT_VERIFICATION_KEY --deployment local
Get-Clipboard | corepack pnpm exec convex env set PRIVY_WEBHOOK_SIGNING_KEY --deployment local
```

Set the non-secret backend App ID, switch the gateway to live mode, and disable mock authentication:

```powershell
corepack pnpm exec convex env set PRIVY_APP_ID "your-app-id" --deployment local
corepack pnpm exec convex env set PRIVY_MODE live --deployment local
corepack pnpm exec convex env remove ALLOW_INSECURE_MOCK_AUTH --deployment local
```

Then update `.env` with the matching public App ID and Client ID and set `PUBLIC_PRIVY_MODE=live`.

## Origins, login, and webhooks

For the web client, allow `http://localhost:5173` on the Privy app client and configure `http://localhost:5173/auth/callback` for the local OAuth return flow. Enable email OTP and Google in the app's login-method settings.

Privy cannot deliver a webhook to `127.0.0.1`. For real webhook testing, expose `http://127.0.0.1:3211/webhooks/privy` through an HTTPS tunnel, add that HTTPS URL under **Configuration → Webhooks**, select the required events, and load the resulting signing key into Convex. Keep the local Convex process running while testing.

## Inspect configuration safely

List only variable names, not their secret values:

```powershell
corepack pnpm exec convex env list --deployment local --names-only
```
